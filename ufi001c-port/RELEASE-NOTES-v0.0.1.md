# UFI001C OpenWrt v0.0.1 — обновление без бэкапа

Дата: 2026-10-25. Профиль: clean. Базовый образ: OpenWrt 25.12.5 (ядро 6.12.94).

Прошивка та же, что в v3.2.14. Изменения только в установщике.
Нумерация комплекта перезапущена с 0.0.1.

## Что изменилось

- `UPDATE.cmd` больше не требует бэкап и вообще его не использует.
  Бэкапы нужны только для возврата модема к стоку (`RESTORE.cmd`).
  Раньше обновление отказывалось работать без папки `backup-*/emmc.bin`,
  а под замороженным exe путь обновления через `ufi-install.py`
  не запускался вовсе. Теперь обновление выполняется внутри
  установщика, тем же EDL, что и установка.
- Безопасность обновления держится на живых проверках, а не на
  сверке с бэкапом: подключённый модем обязан уже нести проверенную
  раскладку OpenWrt (14 разделов, root — mmcblk0p14) и валидный
  загрузочный образ UFI; разделы NV проверяются на непустоту.
  Любое несоответствие — STOP до любой записи. Стоковый или
  неизвестный GPT обновлением не трогается.
- Записываются только boot и system, каждый участок читается обратно
  и сверяется, как при установке. При несовпадении чтения модем
  остаётся в EDL, а правильное действие — повторить `UPDATE.cmd`
  без перезагрузки (откат к стоку без бэкапа невозможен).
- Без бэкапа нет отката к текущему состоянию: обновление перезатирает
  boot и system начисто, настройки, пароль root, пароль Wi-Fi
  и секции Podkop сбросятся к значениям комплекта. Сохраните свою
  прокси-ссылку и настройки заранее.

## Проверки

- Все юнит-тесты комплекта зелёные, включая 4 новых теста пути
  обновления: успешная перезапись только boot и rootfs с обратным
  чтением, отказ на стоковой разметке, отказ на невалидном живом
  boot-образе и отказ на пустом NV-якоре — во всех отказах
  записей ноль.
- Windows-job CI собирает portable runtime и гоняет
  `--self-test` EDL, как раньше.
- Профиль LTE: B1/B3/B5/B8/B38/B39/B40/B41, без B7/B20.
- Аппаратная приёмка обновления на живом модеме ещё требуется:
  первый прогон `UPDATE.cmd` из этого комплекта — и есть проверка.
