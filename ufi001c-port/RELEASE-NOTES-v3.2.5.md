# UFI001C v3.2.5 Clean

Удаление служб восстановления из clean-профиля по требованию владельца:
ufi-modem-watchdog и ufi-lte-health больше не входят в прошивку. Логика
простая: устройство включается, ModemManager поднимает модем, Podkop
автостартует — и всё. Никаких сторожей, которые что-то перезапускают.

Что изменено:

- `clean/ufi001c.config`: `CONFIG_PACKAGE_ufi-lte-health` и
  `CONFIG_PACKAGE_ufi-modem-watchdog` сняты (is not set). В прошивку они
  не попадут.
- `check_config.py`: обе службы перенесены из списка обязательных в список
  запрещённых для clean-профиля — сборка упадёт, если их кто-то вернёт
  в конфиг.
- `check_rootfs.py`: файлы служб убраны из FILES и добавлены в FORBIDDEN —
  собранный rootfs проверяется на их отсутствие.
- `migration/stock_install.py`: установщик со стока отклоняет обе службы
  как неожиданные пакеты (рядом с ufi-care, ufi-service-proxy, zapret-ufi).

Что осталось без изменений:

- Порядок старта rmtfs (START=65, до ModemManager 70) — из v3.2.4.
- DNS-архитектура: bootstrap только через Яндекс 77.88.8.8 TCP 53
  (опция ufi_bootstrap_transport), нужен лишь чтобы резолвить имя прокси
  при старте. Весь пользовательский DNS — 1.1.1.1 через DoH внутри
  XHTTP-туннеля: провайдер не может заблокировать 1.1.1.1 на сети, а
  Яндекс не может ничего зацензурить по DNS.
- Podkop 0.7.24 + DNS-патчи, sing-box engine 1.13.21-pdk-r12, открытый Wi-Fi,
  профиль LTE B1/B3/B5/B8/B38/B39/B40/B41.

Честная оговорка: без служб восстановления заклинивший модем (состояние
failed, как 19.10.2026) сам не оживёт — поможет только перезагрузка стика
вручную. Это осознанный выбор в пользу простоты: ничего в прошивке больше
не перезапускает модем, ModemManager и тем более сам стик.
