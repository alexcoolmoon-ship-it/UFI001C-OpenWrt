# UFI001C OpenWrt v3.2.8 — DNS/списки через туннель + NTP через Яндекс

Дата: 2026-10-22. Профиль: clean. Базовый образ: OpenWrt 25.12.5 (ядро 6.12.94).

Включает все исправления v3.2.7 (интеграция Podkop: dnsmasq, policy routing,
nft, cron — см. нотсы v3.2.7). Новое в v3.2.8:

## Что исправлено

1. **Время подтягивается сразу через Яндекс.** `sync_time_ntp()` теперь
   первым пробует `ntpd -q -p 77.88.8.8` — остальные NTP-серверы
   (194.190.168.1, Google, Cloudflare) оператор блокирует, раньше ntpd
   висел 30 секунд и сдавался. Отстающие часы ломали TLS прокси
   (сертификат не валидировался) — отсюда был мёртвый DNS.
2. **Любой DNS из настроек идёт через туннель.** В sing-box
   `detour=main-out` теперь ставится для любого выбранного DNS,
   кроме Yandex-bootstrap (77.88.8.8/77.88.8.1). Выбор в LuCI:
   Podkop → Settings → DNS Server (можно вписать свой).
   Исключение: DNS, заданный именем хоста, — без detour, иначе дедлок
   bootstrap (имя DoH-сервера не резолвится через ещё не поднятый туннель).
3. **Списки и пакеты через туннель при блокировке прямого доступа.**
   `list_update()` после 10 неудачных попыток пробует
   `curl -x http://127.0.0.1:4534 https://github.com` и при успехе
   выставляет `http_proxy`/`https_proxy`/`PODKOP_LIST_PROXY`.
   Чинит «GitHub unavailable» при обновлении списков и «Нет пакетов»
   в LuCI.

## Обновление

Как обычно: распаковать USB-архив, прошить через EDL/stock_install.py.
`platform_check_image` по-прежнему отклоняет sysupgrade из LuCI.
